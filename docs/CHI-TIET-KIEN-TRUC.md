Nội dung nguyên văn của các mục dài trong CLAUDE.md; CLAUDE.md chỉ giữ bản tóm tắt.

## Giao diện đăng nhập (Login designs)

- **Login designs**: the look of the sign-in/register page is a "design" independent of the public theme; the controllers (`LoginController`, `RegisteredUserController`, `AuthPageContext`) are shared and keep returning `cmsfrontend::screens.pages.auth.login`, whose only content is `@include(LoginDesigns::view())`. A design is a folder `Modules/CmsFrontend/resources/views/auth/designs/<key>/` (`login.blade.php`, `auth.css`, `design.php`); folders are found by scanning (no registration; `_template` is skipped) and `scripts/theme-profiles.mjs` adds every `designs/*/auth.css` to EVERY build, single-theme builds too. Which design a project uses is option `cms_login_designs` (`{project key: design key}`), set in Developer Settings → tab "Đăng nhập" (preview in a sandboxed iframe); no choice = the design named like the project's theme (the behaviour before designs existed); an unknown / not-built / broken choice falls back to theme design → `default`, never a 500. Service `Modules/CmsBackend/app/Services/LoginDesigns.php`; how to add one: `docs/login-designs/HUONG-DAN-THEM-GIAO-DIEN.md`; tests `tests/Feature/Login` (SQLite :memory:). Brand (name, logo) still comes from the project's theme, not from the design. Design `bandean-v2` (from `design-input/loginSBUT`, folder git-ignored) is the theme `bandean-v2`'s own design (`login.design` in `screens.php`; images in `public/assets/img/auth/bandean-v2/`, logo `public/assets/img/themes/bandean-v2/login-logo.png` = `login.logo`): same frame size and motion as `ban-de-an` (the glass half slides between the columns, doors on success), over a background photo; its `auth.css` only adds rounded corners, images/colours and an opaque glass half (own copy of the photo, never see-through).

## Định hướng nghề nghiệp (RIASEC)

- **Career orientation (RIASEC)** is a feature cluster of its own that reuses the survey engine: survey type `career`, admin `/cms/dinh-huong-nghe-nghiep` (routes `cms.nghe-nghiep.*`), public `/dinh-huong-nghe-nghiep` (`cms.frontend.nghenghiep.*`), own permissions `nghenghiep-*`, own Feature Registry switch `career` (independent of `survey`) and own admin menu item. Both clusters are registered from one declaration (`$surveyCluster` in `Modules/CmsBackend/routes/web.php`, loop in `Modules/CmsFrontend/routes/public.php`) and the shared controllers/views use `Support/SurveyCluster` (`name()`, `route()`, `permission()`, `title()`) instead of hard-coded route or permission names; middleware `survey.cluster` keeps a record in its own cluster. Scoring is in `Support/Riasec.php`; Holland code goes to `ks_khao_sat_users.ksu_ket_qua` (+ `ksu_diem`); group texts and suggested majors are edited in admin (tables `ks_career_group`, `ks_career_major`, no hard-coded data); `php artisan survey:career-starter` creates an optional Draft starter set. The new `nghenghiep-*` permissions must be enabled in Developer Settings (Permissions tab) on a deployment that has a permission manifest. Developer Settings: feature permissions are listed (with the owning feature, filterable) in the Permissions tab, `php artisan features:sync-permissions` creates declared-but-missing permission rows, and `multilingual` has its own Languages tab instead of being listed among the features. Details: `docs/survey-module/06-CAREER-ORIENTATION.md`. The SQLite survey tests (`tests/Feature/Survey`) run with `DB_CONNECTION=sqlite DB_DATABASE=:memory: CMS_DB_DATABASE=:memory:` (needs pdo_sqlite; all 152 pass). Note: that suite rewrites `storage/app/developer/permission-manifest.json` of the machine it runs on, so back the file up first. The laravel-filemanager routes are guarded by `App\Http\Middleware\LfmRequireInput` (missing required input = 400, not a package PHP error/500).

## Ghi chú nâng Laravel 12

- **Laravel 12 upgrade notes** (branch `upgrade/laravel-12`): `composer.json` pins `config.platform.php = 8.2.99` so the lock installs on the servers (PHP 8.2). `intervention/image` is v3 (no `Image::make`/facade; see `BannerDataProvider`). The custom `url` binding in `AppServiceProvider` must not call `instance('routes')` again when the collection is unchanged (Laravel 12 rebinds it to the URL generator and recursed until memory ran out). `laravel/jetstream` (and with it Fortify, Passkeys, the two-factor/profile-photo routes) was removed: nothing used it, and its routes duplicated `routes/auth.php` (`verification.*`, `password.confirm`). Login/logout/password routes are the Breeze-style controllers in `app/Http/Controllers/Auth` + `routes/auth.php` (Breeze package itself is not installed). `php artisan route:cache` now works (tested with the main admin pages); `bootstrap/cache` stays untracked, so run it on the server only as part of a deliberate deploy step and `route:clear` after route changes. The old nwidart scaffold resource routes (`cms/cmsbackend`, `cms/cmsfrontend`, `v1/*`) were removed; `CmsBackendController@index` is the dashboard and stays.
